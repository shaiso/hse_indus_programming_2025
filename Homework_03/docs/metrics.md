# Метрики качества AutoDoc API

## Что меряем

| Метрика | Определение | Как считаем |
|---|---|---|
| **Precision** | Доля корректных эндпоинтов среди найденных | `matched / found` |
| **Recall** | Доля найденных эндпоинтов из ожидаемых | `matched / expected` |
| **Spec validity** | Прошла ли OpenAPI 3.0 валидация | `kin-openapi.Validate()` |
| **Latency** | Полное время ответа `/api/v1/analyze` | client-side, ms |
| **LLM latency** | Время вызова LLM (часть total) | server-side, поле `latency.llm_ms` |
| **Cost** | Стоимость запроса в USD | `tokens_in × $0.40/1M + tokens_out × $1.60/1M` (gpt-4.1-mini) |

## Эталонные проекты

В `examples/` лежат три размеченных проекта. Файл `expected_endpoints.json`
содержит истину (`{method, path}` парные).

| Проект | Файлы | Фреймворк | Ожидаемых endpoint'ов |
|---|---|---|---|
| `go_gin_api` | 1 (~50 строк) | Go + Gin | 4 |
| `python_fastapi` | 1 (~50 строк) | Python + FastAPI | 5 |
| `express_api` | 1 (~50 строк) | Node.js + Express | 4 |

## Методика подсчёта матчинга

Эндпоинт считается найденным корректно, если совпадают `(METHOD, normalized_path)`.

`normalized_path` приводит `{userId}` и `{id}` к одному канониcальному
`{*}` — это позволяет не штрафовать модель за выбор имени параметра, который
отличается от размеченного.

Реализация — `tests/quality/quality_test.go`.

## Запуск

### С реальной моделью (полные метрики)

```bash
export OPENAI_API_KEY=sk-...
./scripts/quality_eval.sh
```

### Smoke-тест с mock LLM

```bash
USE_MOCK_LLM=true PORT=8089 go run ./cmd/server &
go test ./tests/quality -v -args -url http://localhost:8089/api/v1/analyze
```

Mock всегда возвращает `/ping` — precision/recall будут 0.0, но
тест пройдёт (валидируется только сама инфраструктура замера).

## Результаты — gpt-4.1-mini (real LLM)

Прогон от 2026-05-21 через `go test ./tests/quality -args -url http://localhost:PORT/api/v1/analyze`.
Провайдер — OpenAI-совместимый прокси AiTunnel (`OPENAI_BASE_URL=https://api.aitunnel.ru/v1`),
модель `gpt-4.1-mini`, `temperature=0`, `response_format=json_object`.

| Проект | Found | Matched | Precision | Recall | Spec valid | Total ms | LLM ms | Tokens (in/out) |
|---|---|---|---|---|------------|---|---|---|
| go_gin_api | 4 | 4 | 1.00 | 1.00 | ok         | 8601 | 8594 | 554/733 |
| python_fastapi | 5 | 5 | 1.00 | 1.00 | ok         | 12389 | 12386 | 607/996 |
| express_api | 4 | 4 | 1.00 | 1.00 | ok         | 11822 | 11819 | 608/1125 |
| **AGG (n=3)** | **13** | **13** | **1.00** | **1.00** | **3/3**    | **10937 avg** | **10933 avg** | **1769/2854** |

Стоимость прогона (OpenAI прайс gpt-4.1-mini, $0.40/$1.60 за 1M токенов):
`1769 × $0.40/1M + 2854 × $1.60/1M = $0.000708 + $0.004566 ≈ **$0.0053**`.

Через AiTunnel один запрос (28 in / 6 out) стоит ~0.01 ₽; полный прогон по 3 эталонам обошёлся в ~1–2 ₽.

### Что означают эти числа

- **Precision/Recall = 1.00 на 3/3 проектах** — на чистых, schema-first примерах
  (FastAPI с Pydantic, Gin с `binding`-тегами, Express без схем) модель восстанавливает
  все эндпоинты без галлюцинаций. На более грязном/неоднозначном коде ожидаемо ниже —
  см. секцию "Где модель ошибается".
- **LLM ≈ 99.97% latency** — `total - llm` стабильно 3–7 мс. Подтверждает, что узкое
  место — внешний API, не наш Go-сервис.
- **Spec validity 3/3** — kin-openapi принял все три ответа с первой попытки,
  `retried_spec=false` во всех случаях.

## Интерпретация и ограничения

### Что хорошо ловит модель

- Чёткие декораторы и роутинг (`@app.get(...)`, `r.GET(...)`,
  `app.get(...)`).
- Schema-first фреймворки (FastAPI с Pydantic) — модель уверенно достраивает
  схемы запросов и ответов.
- Метод и путь — на этих эталонах ожидается **recall ≥ 0.9**.

### Где модель ошибается (известные слабости)

- **Динамический роутинг**: пути, склеенные из переменных
  (`r.GET(prefix+"/users", ...)`) — может не распознать.
- **Нестандартные DSL**: кастомные хелперы поверх Gin/Express, генерирующие
  роуты из метаданных, — модель видит вызов хелпера, не результат.
- **Неполные схемы тел**: при отсутствии типов (Express без Joi/zod) тело
  запроса будет либо пустым, либо `additionalProperties: true`.
- **Галлюцинации параметров**: иногда модель добавляет «логичные»
  query-параметры, которых нет в коде → штрафует precision.

### Зачем эти метрики, а не accuracy/F1

- Для задачи генерации спеки нет фиксированного «класса» — есть множество
  эндпоинтов. Precision/recall — стандарт для retrieval-подобных задач.
- F1 можно посчитать как `2PR/(P+R)`, но в реальной работе важнее
  смотреть на **recall** (мы хотим не пропускать API) при precision не ниже
  ~0.9 (мы не хотим врать о несуществующих).
